Design a star schema & set properties

A good model is narrow, clean and shaped like a star. Everything else (DAX, speed, security) gets easier.

1. Fact tables and dimension tables

Fact tableDimension table
HoldsEvents / transactions (sales, clicks, shipments)Descriptive attributes (customer, product, date, store)
ColumnsForeign keys + numeric values you aggregateOne unique key + text attributes used to slice and filter
RowsMany (usually the biggest tables)Few compared with facts
Relationship side“Many”“One”

In a star schema one fact table sits in the middle and dimension tables connect directly to it. A snowflake chains dimensions (Sales → Product → Subcategory → Category). For Power BI, flatten the chain: merge Subcategory and Category into the Product table in Power Query. Fewer relationships means simpler DAX and faster queries.

  • Avoid one huge flat table that repeats customer / product text on every row (big and slow).
  • Avoid many-to-many relationships between big tables; use a bridge table instead.
  • Build the star in Power Query (shape the data) and verify it in Model view.

2. Column properties (Properties pane in Model or Data view)

PropertyWhat it doesTypical use
Data type / FormatHow values are stored and displayedCurrency, percentage, date format
Summarize byDefault aggregation when dragged to a visualDon’t summarize for IDs and keys, years, ratings
Sort by columnSorts one column by anotherMonth name sorted by Month number
Data categoryTells Power BI what the values meanCity, Country, Latitude, Longitude, Web URL, Image URL (correct maps / links)
Hide (in report view)Removes the field from the Data pane for report authorsForeign keys, helper columns. The column stays in the model.
Display folderGroups fields in the Data pane“Sales measures”, “Dates”
DescriptionTooltip for report authorsExplain a measure’s definition

A table also has a name and description. Measures live in a home table (often a dedicated, empty “_Measures” table).

Exam trapMonths sorting as April, August, December…? Set Sort by column to the month number. Hiding a column does not delete it: it can still be used in relationships and DAX.
Key takeaways
  • Facts = numbers + foreign keys; dimensions = unique key + descriptions.
  • Flatten snowflakes into a star; avoid many-to-many.
  • Sort by column, Don’t summarize and Data category are the three properties tested most.
