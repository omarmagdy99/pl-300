Power Query Editor & data profiling

Find out what is wrong with your data before you fix it.

1. The editor layout

  • Queries pane (left) — all queries and groups.
  • Data preview (center) — a sample of the data.
  • Query Settings (right) — Name, Properties, and Applied Steps. Every step is stored as M code.
  • Formula bar — M for the selected step. Advanced Editor shows the whole query.
  • View → Query Dependencies shows how queries feed each other.

2. The three profiling tools (View tab → Data Preview)

ToolWhat it shows
Column quality% of Valid, Error and Empty values per column
Column distributionFrequency bar chart + count of distinct and unique values per column
Column profileDetailed statistics (count, min, max, average, std. dev. …) and value distribution for the selected column

3. Distinct vs unique

MeaningValues 1,1,2,3
DistinctNumber of different values (each counted once)3
UniqueNumber of values that appear exactly once2

A column is a good key for the “one” side of a relationship when distinct = unique = row count and there are no empty or error values.

4. Profiling scope

By default profiling is based on the top 1,000 rows. To profile everything, click the status bar at the bottom-left and choose Column profiling based on entire data set.

Exam trapProfiling results exist only inside the Power Query Editor. They are not stored in the model or shown in the report.
Key takeaways
  • Column quality → valid / error / empty. Column distribution → distinct & unique.
  • Default sample = 1,000 rows; switch to the entire data set when you need accuracy.
  • Applied Steps = the recipe; each step is one line of M.
