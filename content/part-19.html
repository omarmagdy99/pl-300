Workspaces & roles

A workspace is where a team builds and manages Power BI content. Roles decide who can do what.

1. What a workspace holds

  • Semantic models (datasets), reports, dashboards, dataflows, paginated reports (and other Fabric items).
  • My workspace is your personal area: no collaboration and no apps. For teamwork create a workspace: Workspaces → New workspace (name, description, contact list, license mode: Pro, Premium per user, Premium capacity or Fabric).
  • Publish from Desktop with Home → Publish, or upload a .pbix in the service (New → Upload a file). Publishing again with the same name replaces the model and report.
  • Lineage view shows how data sources, dataflows, semantic models and reports depend on each other.

2. Workspace roles

RoleCan doCannot do
AdminEverything: delete the workspace, add or remove anyone including other admins—
MemberAdd members with a lower or equal role (members, contributors, viewers), publish / update the app, share items, create and edit contentDelete the workspace, add admins
ContributorCreate, edit and delete content, publish reports, schedule refreshPublish or update the app, manage access
ViewerView and interact with reports and dashboardsEdit or create content. Row-level security applies to viewers
  • Assign security groups (Microsoft Entra / Microsoft 365 groups) instead of individuals: easier to manage.
  • Give the least privilege that still lets the person do their job.

3. Licenses

  • Free: personal use in My workspace; cannot consume shared content unless the workspace is on Premium / Fabric capacity.
  • Pro: share, collaborate and publish to workspaces. Viewers also need Pro on shared capacity.
  • Premium per user (PPU) / Premium or Fabric capacity: larger models, more refreshes, deployment pipelines, paginated reports. On capacity-backed workspaces free users can view content.
Exam trapRLS restricts Viewers only. Workspace Admins, Members and Contributors can edit the model, so RLS does not filter what they see. To test RLS as a real restricted user, make them a Viewer.
Key takeaways
  • Admin > Member > Contributor > Viewer; only Admin adds admins; Contributors can’t publish the app.
  • Add groups, not people, and use the lowest role that works.
  • Viewers on shared capacity need a Pro license.
