Tables, matrices, KPIs & paginated reports

Detail views, status indicators, and when a Power BI report is not the right tool.

1. Table and matrix

TableMatrix
LayoutFlat rows and columnsRow and column headers (cross-tab)
HierarchiesNoYes: expand / collapse rows, drill down
TotalsGrand totalSubtotals and grand totals (can be switched off)
  • Matrix options: stepped layout, subtotals on rows / columns, show values on rows, +/- expand buttons.
  • Sparklines: in a table or matrix, open the field’s menu in the Values well → Add a sparkline to show a mini trend per row.
  • Add conditional formatting (data bars, icons, colors) to cells.

2. Cards, KPI and gauge

VisualShows
Card / multi-row cardOne or a few key numbers
KPICurrent value vs a target, a trend axis and a status color
GaugeProgress of a value between a minimum and maximum, with an optional target

3. Other useful visuals

  • Line and clustered column: a measure as columns and another as a line on a secondary axis.
  • Waterfall, funnel, ribbon, treemap, scatter with a Play axis (animation over time).
  • R / Python visuals for custom plots (script visuals).
  • Custom visuals from AppSource (“Get more visuals”). Prefer certified visuals.

4. Paginated reports

  • Pixel-perfect, printable documents that can span many pages: invoices, statements, labels.
  • Authored in Power BI Report Builder (not Power BI Desktop); published to a workspace on Premium / Fabric / PPU capacity.
  • Export to PDF, Word, Excel. Interactive exploration is better in a normal Power BI report.
Exam trap“Value against a target with a trend” → KPI. “Printable invoice with repeating headers” → paginated report. “Mini trend in each table row” → sparkline.
Key takeaways
  • Matrix = hierarchies + subtotals; table = flat detail.
  • KPI = value + target + trend; gauge = value on a scale.
  • Paginated reports are built in Report Builder for pixel-perfect output.
