Optimize model performance

Smaller models refresh faster and answer faster. Measure first, then fix the real bottleneck.

1. Make the model smaller

  • Remove columns and rows you don’t need (before loading, in Power Query).
  • Lower cardinality: split DateTime into Date and Time (or keep only the date), round long decimals, avoid GUID / unique-text columns in big tables.
  • Use the right data types (integers compress better than text).
  • Turn off Auto date/time and use one date table.
  • Do calculations in the source or Power Query rather than as calculated columns on large tables.
  • Choose the right granularity: do you really need one row per second, or is daily enough? Use aggregation tables (user-defined aggregations) with DirectQuery.
  • Star schema, single-direction relationships, no unnecessary many-to-many.

2. Find the slow parts

ToolUse it to
Performance Analyzer (View → Performance analyzer → Start recording → Refresh visuals)See how long each visual takes, split into DAX query, Visual display and Other; copy the visual’s DAX query
DAX query viewWrite, run and test DAX queries (paste the copied visual query here) and see a measure’s results
DAX Studio / Tabular Editor / VertiPaq Analyzer (external)Server timings, column sizes, best-practice rules

Reading the result: a high DAX query time means a slow measure or model; a high Visual display time means too many data points or a heavy visual; a high Other time means the visual waited for other visuals.

3. Write faster DAX

// slow: [Total Sales] is evaluated three times
Margin % bad =
IF ( [Total Sales] > 0, ( [Total Sales] - [Total Cost] ) / [Total Sales], BLANK () )

// better: variables evaluate once and read better
Margin % =
VAR Sales = [Total Sales]
VAR Cost  = [Total Cost]
RETURN
    DIVIDE ( Sales - Cost, Sales )
  • Use VAR, DIVIDE and Boolean filters; avoid FILTER ( WholeTable, … ) when a column filter works.
  • Prefer measures to calculated columns; avoid bi-directional filters and many-to-many on big tables.

4. Report-level tips

  • Fewer visuals and slicers per page; use Top N or filters to limit data points.
  • Query reduction: add an Apply button to slicers/filters.
  • Large data: incremental refresh, DirectQuery or composite models.
Exam trapBi-directional relationships and calculated columns usually make a model bigger or slower, not faster. To find a slow visual use Performance Analyzer; to test its DAX use DAX query view.
Key takeaways
  • Remove columns/rows, lower cardinality, disable Auto date/time.
  • Performance Analyzer finds the slow visual; DAX query view runs its query.
  • Use variables and DIVIDE in measures.
