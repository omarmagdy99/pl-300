Refresh & gateways

Published data goes stale unless you refresh it. Know what needs a refresh, and what needs a gateway.

1. What needs refreshing?

Storage modeRefresh
ImportNeeds scheduled or manual refresh (the copy of the data is in the model)
DirectQuery / live connectionNo data refresh: queries go to the source. Dashboard tiles are cached and refreshed periodically; auto page refresh can update visuals
  • Configure in the service: semantic model → Settings → Scheduled refresh (time zone, times, failure notifications). Refresh now runs it immediately.
  • Limits: about 8 refreshes per day with Pro, up to 48 with Premium / PPU / Fabric capacity.
  • Credentials and privacy levels are set under Data source credentials in the model settings.
  • Parameters can be edited in the service under Parameters.

2. On-premises data gateway

A gateway is software installed on a machine inside your network that lets the service reach on-premises sources (SQL Server on a server, file shares). Cloud sources (Azure SQL, SharePoint Online) do not need one.

Standard (enterprise) modePersonal mode
UsersMany users and reports; can be clusteredOne user
SupportsImport, DirectQuery and live connectionsImport only
Install onA shared server that is always onA personal computer

After installing: add the data source to the gateway (or map the model’s source to it) and supply credentials, then schedule the refresh.

3. Incremental refresh

For large tables, refresh only recent data instead of everything.

  1. In Power Query create two Date/Time parameters named exactly RangeStart and RangeEnd.
  2. Filter the table’s date column: >= RangeStart and < RangeEnd (ideally folded to the source).
  3. Right-click the table → Incremental refresh: choose how much history to store and how recent a period to refresh.
  4. Publish; the service creates partitions and refreshes only the newest.

4. Dataflows

A dataflow is Power Query running in the service. It stores cleaned data that many semantic models can reuse, with its own refresh schedule.

Exam trapDirectQuery needs no scheduled refresh but an on-prem source still needs a standard gateway. A personal gateway cannot serve DirectQuery. RangeStart / RangeEnd must be Date/Time and spelled exactly.
Key takeaways
  • Import = refresh; DirectQuery = no refresh. 8/day Pro, 48/day Premium.
  • On-premises source → gateway (standard for shared use and DirectQuery).
  • Incremental refresh = RangeStart + RangeEnd + a policy.
