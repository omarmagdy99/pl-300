Performance, parameters & M

Make queries fast, reusable and ready to load.

1. Query folding

Query folding means Power Query translates your steps into one native query (for example SQL) that runs at the source, instead of pulling all data and transforming it locally.

  • Usually folds: filter rows, remove / rename / choose columns, sort, group by, merge/append of the same source.
  • Often breaks folding: Add Index Column, custom functions, merges across different sources, Table.Buffer.
  • Verify: right-click a step → View Native Query. If it is greyed out, the step does not fold.
  • Best practice: put foldable steps (filters, column removal) first.

2. Parameters

  • Home → Manage Parameters → New Parameter: name, type, suggested values (Any value, List of values, Query), current value.
  • Use them for server / database names, file paths, filter values.
  • After publishing, edit them in the service: Semantic model settings → Parameters (no Desktop needed).
  • RangeStart and RangeEnd (Date/Time type, exactly these names) enable incremental refresh.

3. Load options & model size

  • Uncheck Enable load on staging / helper queries so they aren't loaded into the model.
  • Include in report refresh controls whether the query refreshes.
  • Remove unused columns, filter unneeded rows early, use proper types, avoid high-cardinality columns (split DateTime into Date + Time).
  • Finish with Close & Apply.

4. Reading M

let
    Source  = Sql.Database("srv-prod", "Sales"),
    Orders  = Source{[Schema="dbo", Item="Orders"]}[Data],
    Recent  = Table.SelectRows(Orders, each [OrderDate] >= #date(2024,1,1)),
    Slim    = Table.SelectColumns(Recent, {"OrderID", "OrderDate", "Amount"})
in
    Slim
  • let … in — each line is a named step; the last one after in is the result. Applied Steps = these names.
  • M is case-sensitive (Table.SelectRows ≠ table.selectrows).
  • each is shorthand for a function with the row as _.
  • M is for loading / shaping; DAX is for calculating in the model — they are not interchangeable.
Exam trapDisabling load doesn't delete a query — other queries can still reference it. And “Index column” in a SQL source stops folding for the steps after it.
Key takeaways
  • View Native Query enabled = step folds.
  • Parameters make Dev → Prod switching and incremental refresh possible.
  • Smaller model: fewer columns, fewer rows, no loading of staging queries.
