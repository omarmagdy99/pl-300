DAX fundamentals: measures & context

Know what to put in a measure, what to put in a column, and which context DAX is working in.

1. Three kinds of calculations

Rule of thumb: if it should change with filters, make a measure. If you need to put it on an axis or in a slicer, make a column (preferably in Power Query or the source).

2. Row context and filter context

  • Row context = “the current row”. It exists in calculated columns and inside iterators (SUMX, AVERAGEX, FILTER).
  • Filter context = the set of filters currently applied: slicers, filters pane, the row/column of the visual cell, and relationships.

3. Aggregators and iterators

Total Sales  = SUM ( Sales[Amount] )
Orders       = COUNTROWS ( Sales )
Customers    = DISTINCTCOUNT ( Sales[CustomerID] )
Avg Price    = AVERAGE ( Sales[UnitPrice] )

// iterator: calculates row by row, then sums
Revenue = SUMX ( Sales, Sales[Quantity] * Sales[UnitPrice] )

// safe division: returns BLANK (or the 3rd argument) when the denominator is 0
Margin % = DIVIDE ( [Profit], [Revenue] )

// look up a value from the "one" side in a calculated column
Category = RELATED ( Product[Category] )

Status = SWITCH ( TRUE (), [Margin %] >= 0.3, "High", [Margin %] >= 0.1, "Medium", "Low" )
  • SUM ( Sales[Quantity] * Sales[UnitPrice] ) is invalid: SUM takes one column. Use SUMX.
  • RELATED follows a relationship from the many side to the one side; RELATEDTABLE goes the other way.

4. Quick measures, implicit vs explicit

  • Quick measures (right-click a field → New quick measure) generate DAX for common patterns: running total, year-over-year change, weighted average, percent of total.
  • Implicit measures appear when you drag a numeric column to a visual. Explicit measures are written by you: reusable and recommended.
  • Reference a measure as [Total Sales] and a column as Table[Column].
Exam trapA calculated column cannot react to slicers (it is computed at refresh). DIVIDE never throws a divide-by-zero error; it returns blank or the alternate result.
Key takeaways
  • Measure = filter context, query time. Column = row context, refresh time.
  • Use SUMX when you must multiply per row before summing.
  • Prefer explicit measures and DIVIDE.
