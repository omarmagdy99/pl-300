Governance: labels, endorsement & pipelines

Classify data, mark trusted content, understand dependencies and release changes safely.

1. Sensitivity labels

  • Labels (for example General, Confidential) come from Microsoft Purview Information Protection and are enabled by an admin.
  • You can apply them to semantic models, reports, dashboards and dataflows in Desktop and the service.
  • The label and its protection follow the data when it is exported to Excel, PowerPoint or PDF, and can be inherited by downstream content.
  • Admins can make labeling mandatory.

2. Endorsement

LevelMeaningWho
Promoted“This is ready to use”Any user with edit permission on the item
CertifiedReviewed and meets organizational standardsOnly authorized reviewers chosen by an admin
Master dataThe authoritative source of a type of dataAuthorized users (for data items)

Endorsed items rank higher in search and show a badge, which helps people find the right model and avoid duplicates.

3. Lineage, impact and usage

  • Lineage view: the chain data source → dataflow → semantic model → report / dashboard.
  • Impact analysis: before changing a model, see which reports and dashboards downstream would be affected (and notify their contacts).
  • Usage metrics report: who views your report and how often.
  • Admins use the Admin portal (tenant settings such as who can export or publish to web) and activity / audit logs.

4. Deployment pipelines

A deployment pipeline moves content through Development → Test → Production; each stage is a workspace. You can compare stages and set deployment rules (for example a different data source or parameter value per stage). They need Premium / PPU / Fabric capacity, not a Free license.

Exam trapEndorsement shows trust; sensitivity labels protect data; RLS restricts rows. “Which reports break if I change this model?” → Impact analysis, not Usage metrics.
Key takeaways
  • Promoted = any editor; Certified = authorized reviewer.
  • Sensitivity labels persist on export.
  • Pipelines = Dev → Test → Prod with rules; lineage + impact analysis show dependencies.
